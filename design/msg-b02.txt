fix(batch 02): 盘符推导、无盘判定、读盘移出 UI 线程、保存顺序、卸载收尾

F1 多光驱盘符：设备路径 \\.\F: 的 letter 原为 ':'（trimEnd 后取最后字符拿到冒号），
  chip 全显示 ':'，selectDrive 还会把 ":" 写进设置。新增 driveLetterOf()，
  只在能取出单字母时返回大写盘符，否则留空表示「自动」；selectDrive 校验单字母。

F2 UI 线程读盘：exportAlbumJson / previewPlan / testDisc / ripFirstTrack / ripAlbum
  都在宿主 UI 线程先 freshScan()，空盘或驱动挂起时界面冻十几秒；testDisc 与
  ripFirstTrack 的 busy 判断还在扫描之后，双击会并发进两条。现在 busy 先判、
  扫描进工作线程（新增 onWorkerWithScan），ripAlbum 的准备状态也移至线程内。

F4 空盘判定不再看文案：ScsiMessages.isNoDisc() 只看 sense/Win32 码
  （ERROR_NOT_READY 21、KEY=2 + ASC 0x3A/0x04/0x3C）；英文/日文界面下
  原先按「没有光盘」中文子串匹配会失败，没盘被当故障并指数退避到 30 秒。

F3 读盘失败后能自愈：DiscWatcher.reportFailure 现在清 lastFingerprint/lastHadDisc，
  恢复时即使指纹相同也会重建面板，不再永久停在「读不到光盘」。

F5 手动元数据不再先说成功：写盘前只提示「正在保存元数据…」，落盘成功才宣布；
  读不到盘/写失败时重开手填面板并保留草稿，用户换盘后可再点保存。

F6 卸载收尾：SaltAudioCopyPlugin.stop() 调 ConfigActions.shutdown()，
  置取消标志并 shutdownNow 两条工作线程，避免卸载后仍在写盘。
