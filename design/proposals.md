## 1. 八个方案

### A. 右下角浮卡（0.28 的改良版）— `A-右下浮卡.png`
- **入口**：在 CD 工具箱页右下角常驻一张小卡。
- **内容**：标题 + 盘摘要 + 状态/进度 + 「暂停/取消」（空闲时是「扫描/抓整盘」）。扫描、抓整盘、设置都在卡里一行。
- **优点**：改动最小（0.5 轮），随时可见进度。
- **缺点**：仍是浮层，**没有真正解决「和旁边内容抢位置」**；宿主的播放条在底部中央，某些窗口尺寸下仍可能挨着。
- **适合**：只想先止血、尽快可用。

### B. 侧边栏独立页面「盐专辑」— `B-侧边栏页面.png`
- **入口**：左侧导航新增一项「盐专辑」（和 歌曲/专辑/设置 并列）。
- **内容**：整页布局——左封面 + 候选缩略图，右音轨表（轨号/标题/时长/状态/单轨进度），底部操作栏 + 输出路径。
- **优点**：最像 EAC，信息容量最大，**完全不与 CD 工具箱抢位置**。
- **缺点**：⚠️ 宿主**没有注册路由的 API**。要真正加一页，只能 hook 侧边栏列表构建器（`androidx/compose/ui/ξ` 的 `LazyListScope`）插入一项，再让点击打开**我们自己的窗口**——即「入口在侧边栏，页面是自建窗口」。伪装成页面的代价是：宿主改版时侧边栏混淆类名一变就失效。
- **工作量**：入口 hook 1 轮 + 页面本身 1–2 轮。

### C. 独立可隐藏浮窗 + 收起胶囊 — `C-独立浮窗.png` ⭐
- **入口**：插件自己在宿主窗口之上开一个窗口（和社区里的「桌面歌词」插件同一路子），标题栏可拖动/最小化；最小化后收成右下角一颗胶囊「盐专辑 · 62% >」。
- **内容**：封面、盘信息、进度、输出目录、两个模板框 + 变量块；高级项在插件配置页。
- **优点**：**真·可隐藏**，完全不占宿主布局、不和任何东西抢位置；可以移到第二块屏幕；窗口尺寸/位置可记住。
- **缺点**：多一个窗口要管理（关闭/重开、焦点、DPI）；首次打开要在插件里点一下「打开盐专辑」。
- **工作量**：1 轮左右（ComposeWindow + 胶囊态 + 位置持久化）。

### D. CD 工具箱页内嵌区块（可折叠）— `D-页内区块.png`
- **入口**：CD 工具箱页标题下方的整宽卡片，可折叠。
- **优点**：风格最统一，看起来就是宿主页面的一部分。
- **缺点**：⚠️ `afterComposable` 插入的是覆盖式容器，**内容从页面原点开始画**（0.27 截图里压住标题就是这个原因），要做到「按页面流排版」需要 hook 到宿主内部的 Column/LazyColumn 构建器，属于强耦合。实际做出来大概率还是浮层。
- **工作量**：2 轮起，且不稳定。

### E. 底部 Dock 控制条 — `E-底部Dock.png`
- **入口**：紧贴播放条上方、横跨内容区的一条。
- **优点**：一行看完所有信息，占的垂直空间最小；像播放器，符合直觉。
- **缺点**：浮层贴在底部，**和宿主播放条是同一条视觉带**，容易打架（你截图里已经能看到这个风险）。
- **工作量**：0.5 轮。

### F. 全部收进插件配置页（无面板）— `F-仅配置页.png`
- **入口**：宿主 设置 → 插件 → 盐专辑。
- **优点**：**最稳、最省事**，天然完全一致的设计语言，零 Hook 风险；进度用 toast + 日志。
- **缺点**：抓轨时想暂停/看进度要切到设置页；浪费了「CD 页」这个天然入口。
- **工作量**：0.3 轮（把现有面板内容搬过去）。

### G. 右上悬浮按钮 + 侧边抽屉 — `G-悬浮按钮抽屉.png`
- **入口**：CD 页右上角一颗圆按钮，点开右侧抽屉。
- **优点**：默认几乎不占地方；抽屉宽度可控。
- **缺点**：抽屉仍会盖住页面右侧；比 A 多一次点击。
- **工作量**：0.7 轮。

### H. 「盐专辑」页 + EAC 式步骤向导 — `H-向导式页面.png`
- **入口**：同 B（侧边栏），但页面内是 5 步向导 + 曲目卡片网格。
- **优点**：把「识别 → 选版本 → 检查设置 → 抓取 → 完成」显式化，最贴近 EAC 的心智模型，也最不容易踩错。
- **缺点**：工作量最大（2–3 轮），且继承 B 的入口脆弱性。
- **适合**：确定要长期维护、愿意为入口付代价。

## 2. 能力边界（不会因为选方案而改变）

| 能力 | 现状 |
|---|---|
| 宿主毛玻璃 | 窗口级效果，插件只能半透明近似 |
| 新导航路由 | 无 API；只能 hook 侧边栏列表 + 自建窗口伪装 |
| 新页面内容 | 只能浮层覆盖，无法加入宿主页面流 |
| 自定义图标/字体 | 可以（自绘 Compose），但拿不到宿主图标字体 |
| 快捷键 | 有 `key-bindings` 权限，可做「开始/暂停抓轨」 |
| 多语言 | 已实现（中/英/日，跟随宿主） |

## 3. 推荐

**首选：C（独立可隐藏浮窗）+ 侧边栏入口（B 的入口部分）**
- 用 C 解决「不抢位置、可隐藏」；侧边栏那一下只是「打开浮窗」，即使宿主改版导致入口失效，浮窗仍能从插件配置页打开 —— 有降级路径，不是全盘失灵。
- 常用操作（扫描/抓整盘/暂停/取消/打开目录）留在浮窗；模板、编码、校验、测试动作留在配置页。
- 预估：入口 0.5 轮 + 浮窗 1 轮 + 配置页整理 0.5 轮。

**次选：F**（只要稳定、不在乎入口）
**再其次：A / E**（止血版，仍会与页面内容共存于同一空间）

## 5. 【已作废】早先对 D 的误判（原因见 §7）

**结论：D 做不到「真正插进宿主页面流」。** 证据链：

1. 宿主 CD 工具箱页的渲染器只有一个：`androidx/compose/ui/ݩ.class`（18,390 B），描述符
   `(Landroidx/compose/ui/ঘ;Landroidx/compose/runtime/Composer;II)V`；全仓 4,611 个
   `androidx/compose/ui/` 单层类里只有它匹配。
2. 该参数 `androidx/compose/ui/ঘ` 继承 `androidx.lifecycle.*`（ViewModel），字段是
   `StateFlow<List<…>>` —— 即**驱动器列表的 ViewModel**，不是布局作用域（`ColumnScope` /
   `LazyListScope`），所以 `appendContent` 用不上（宿主实现要求第 4 个 String 参数指向
   `Function1` 内容 lambda，否则抛 `UI parameter ... is not an ordinary Function1`）。
3. 页面自己的排版是在**自身方法体内**用 `ColumnKt.columnMeasurePolicy` / `RowKt.rowMeasurePolicy`
   内联构建的（常量池 #135/#136）。插件 hook 注入的内容落在**页面调用者**的布局里
   （`ComposableSingletons$AppNavigation_desktopKt` 的 `Box`），拿不到页面内部 Column 的插槽。
4. 这正是 0.27/0.28 表现为「浮层压住页面标题」的原因，与配色无关。

→ 因此按用户指示走 **E（底部信息坞）**，并用「避开播放条 + 避开页面内容」的定位消除打架。

## 7. 更正：D 其实可行（读官方 hook 文档 + 重做侦察后）

**我之前错在哪**：我 hook 的是「CD 工具箱整页」（`androidx/compose/ui/ݩ.Ϳ`），它被
`ComposableSingletons$AppNavigation_desktopKt` 在 **Box** 里调用，所以插件内容只能叠在页面上。
官方文档明确：`afterComposable` 是「在所选组件正常返回后追加内容」，追加位置是**该调用的调用者布局**；
而 `appendContent` 只对普通构建回调（如菜单）有效，「不支持直接追加到 Composable lambda」。
→ 正确的做法是：**把 hook 目标换成页面 Column 里的子组件**，内容就会成为 Column 的子项（真正流式）。

**重新侦察的硬证据**（`D:\deepseek\workspace\projects\salt-rip\out\hostcls`）：
1. 页面 `androidx/compose/ui/ݩ` 自己有一个私有合成方法
   `private static final kotlin.Unit Ϳ(Landroidx/compose/ui/ঘ;Landroidx/compose/foundation/layout/ColumnScope;Landroidx/compose/runtime/Composer;I)`
   —— 就是 `Column { … }` 的内容 lambda（**参数里有 ColumnScope**）。
2. 该 lambda 里恰好调用了两次宿主组件：
   `com/xuncorp/voxzen/ui/component/ރ.Ϳ(Landroidx/compose/ui/Modifier;Landroidx/compose/runtime/Composer;II)V`
   与 `…ރ.Ԩ(同上)`（字节码偏移 83 / 118），且**只在这两处**调用。
3. 因此 `afterComposable(className="com.xuncorp.voxzen.ui.component.ރ", methodName="Ԩ",
   inClass="androidx/compose/ui/ݩ")` 追加的内容会落在页面 Column 里 → **D 可实现**，
   并且会像页面内容一样被排版（把下方内容顺延，而不是覆盖）。

**代价与风险**：
- 依赖宿主混淆名（`androidx/compose/ui/ݩ`、`com/xuncorp/voxzen/ui/component/ރ` 的方法 `Ϳ`/`Ԩ`），
  宿主升级会变；缓解：启动时按「描述符 + 调用者唯一性」动态定位，失败自动退回底部坞（E）。
- 只能出现在 CD 工具箱页里（正好符合需求）。

## 8. D′ 设计（页内区块，玻璃质感，浅色/深色）

- 位置：设备行下方，页面 Column 内；宽 = 页面内容宽（左右各 24dp 边距），高 136dp，圆角 20dp。
- 材质：宿主 `surfaceContainerHigh` 以 **≈0.55 透明度**叠加在页面壁纸上 + 1px `outlineVariant` 边 + 顶部 20% 高光；
  深色下改用 `surfaceContainerHighest` + 8% 白色边，避免「黑块」。
- 三行内容：
  1. 封面 64×64 · 专辑名（18 粗）· `20 轨 · 1:18:54 · CD-DA · 已找到 1 个候选`
  2. 进度条（300dp）· `第 7/20 轨 · 62%` · `5.1x · 剩余 1 分 12 秒`
  3. 输出预览 `…\\05 Lovin' You.wav` · 右侧动作 `抓整盘`（实心）`暂停` `取消` `设置`
- 混色规则（避免与宿主打架）：底色只取宿主 token 的 alpha 变体，强调色只给主按钮与进度条；
  不使用纯白/纯黑大面积填充。
