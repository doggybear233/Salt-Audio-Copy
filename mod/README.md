# 盐专辑 (Salt Audio Copy) — Salt Player 抓轨 Mod

Windows 上把 CD 精确抓成 WAV + CUE + 日志，并把专辑信息（MusicBrainz / gnudb / Cover Art Archive）一起落盘。
算法与参数来自对 EAC 1.8 的逆向（见 `../architecture.md`、`../features.md`）。

## 0.38.1（全量中文化收尾、暂停也能抽盘、抓完可见状态、日志 BOM）

对着 0.38.0 的真机复测（B7 / C2 / C3 / C4 / C5 / A3）逐条修。

- **A3 全量翻译**：设置页左列 8 个页名改用 `Strings.message`（之前只翻了右侧子菜单，左边仍是中文）；模板变量块、`%s 项` 计数、暂停/重读提示、`AlbumRipper` 里 36 条阶段与告警、预览/自检摘要、元数据说明都进了 `messages-i18n.json`（现 315 条）。新增 `MessageCoverageTest`：从源码里抓出所有 `Strings.message/fmt` 的字面量，缺一条 en/ja 就失败。
- **B7 暂停时也能抽盘**：`DiscWatcher` 原来 `if (PanelState.busy) continue`，暂停也算 busy，于是抽盘两秒后才发现；改成 `busy && !paused`（暂停时没有 SCSI I/O，探测安全）。
- **C2 同名文件的副本要说清楚**：默认策略 `suffix` 遇到上次留下的同名文件会写成 `01 xxx (2).wav`，现在抓完会多一条警告，说明「要替换就在 设置 → 输出位置 → 同名文件已存在时 选「覆盖」」。
- **C2b `.errors.txt` 不再乱写**：原来 `notes` 里只要有「元数据副本」这类信息行就写错误报告；现在只在这个版真的出过错（有坏轨或有警告）时才写。
- **C3 抓完看得见**：`ReadyBlock` 里补一行 `✓ 已抓完 · N 轨 · 用时 X 秒`（之前这条状态只在抓轨中显示）。
- **C4 重新抓取的确认文案**：说明「再点一次才开始」、「按当前覆盖策略会覆盖/跳过/另存」，并提示「点取消或换盘可解除确认」。
- **C5 日志开头加 UTF-8 BOM**：记事本/部分编辑器对无 BOM 的 UTF-8 会按 ANSI 猜，文件后半段有中日文时整段变乱；CUE 不加 BOM（部分播放器会读坏）。
- 421 项自动化测试全绿；包 1,207,782 B。

## 0.36.5（各国语言标签 / 默认限速 / 抓完状态 / 手填封面）

四个用户反馈一起修：

- **WAV 标签乱码（真 bug）**：`LIST/INFO` 规范是 **ANSI** 字符串，旧代码把 UTF-8 直接写进去，
  于是「灰かぶり」在资源管理器里变成「轣ｰ縺九・繧」。现在写两块：
  `LIST/INFO`（**逐字映射**：系统 ANSI 能表的字符照原样，表不了的换 `?` 且连续只留一个；
  整串都映射不了就干脆不写该字段）+ `id3 `（ID3v2.3 / UTF-16LE，无损）。
  ffprobe、宿主 Salt Player、支持 ID3 的播放器读到的永远是正确文本；
  「资源管理器属性页」受 ANSI 限制，只能做到「能对应就对应」——
  日文、俄文完整；简体（如「红豆」→「?豆」）、繁体、日文汉字能显示大部分；
  韩文、阿拉伯文、emoji 在日文系统上无法编码（韩文/阿拉伯文则不写该字段，宁缺勿乱）。
  顺带修了 `id3 ` 块的 RIFF 长度写成大端的 bug（写入两次后块结构就坏了）。
- **抓轨限速默认 8x**：`driveSpeed` 默认从「不干预（全速）」改成 `1200`（8x），
  选项补到 16x / 24x，并写清「全速时噪音大、重读更频繁、剩余时间更抖」。
- **抓完有明确状态**：整盘抓完后状态行变成「已抓完 · N 轨 · 用时 X 秒」，主按钮变「重新抓取」；
  第一次点只会提示「再点一次确认」，换盘 / 重新扫描 / 点取消都会解除这层确认。
- **保存后要再开一次手动填写才显示新名字（0.36.5 修）**：保存的落盘步骤里先调
  `freshScan()`，它内部会 `Discs.publish()` 重建盘摘要——此时 JSON 还没写，
  缓存是空的，刚显示的名字/封面被刷回「未知」。现在扫描后立刻把乐观值盖回去，
  写完文件再从缓存重建一次（补真实 DiscID 与封面），中间不再有空窗。
- **手填的元数据两秒后又变回「未知」（0.36.4 修）**：换盘监视每 2 秒重扫一次，
  以前每次都由 `Discs.publish()` 用空名字重建 `DiscInfo`，于是保存成功的名字被抹掉。
  现在「盘指纹没变」时只刷新缓存、**不重写面板状态**；重建时也会先读本地 `album.json`
  （含手填的名字与封面），所以插盘/换回同一张盘都能显示上次填的内容。
  坞上的封面在候选为空时退回本地封面（手导的那张），不再只有「CD」占位。
  扫描日志也从「每次扫写一行」改成「只在换盘时写」。
- **点保存后坞上不刷新（0.36.3 修）**：保存动作原来排在单线程工作队列里，
  前面若卡着一次「自动查元数据」（CDDB 镜像连不上时能等几十秒），面板就一直显示旧名字。
  现在**先立刻用草稿改面板状态**（歌手/专辑/轨数），再把写 JSON 丢到独立的保存线程；
  文件选择框也各自单开线程（模态框会一直占着线程，放在工作队列里会堵住抓轨）。
- **换封面时文件框里看不到图片（真 bug，0.36.2 修）**：`FileNameExtensionFilter` 收的是
  `vararg`，旧代码把 `"jpg;jpeg;png;webp"` 当**一个**扩展名传进去，于是列表为空、
  只有切「所有文件」才看得见。现在逐项传，并补 bmp/gif/jfif，另加「所有文件」备选过滤器；
  选 bmp/gif 也会按正确 mime 落盘与内嵌。
- **手填元数据可以导入封面**：没有网络元数据的盘，在「手动填写元数据」底栏点「导入封面…」，
  选好的图片会随 `album.json` 存成 `<discId>.album.cover.jpg`，抓轨时自动写 `cover.jpg`
  并在 FLAC 里嵌入（读缓存时 `MetaOverride.load` 会自动带上这张封面）。

## 0.35.0（剩余时间重做：不再乱跳、不再变大）

上一版的剩余时间是 `已用时间 ÷ 已完成扇区 × 剩余扇区`——**累计平均**，中途遇到一张
慢轨（或 secure 模式疯狂重读）平均值就被拉高，剩余时间会往回涨。这一版换算法：

- **只看最近 12 秒的速度**（窗口首尾两点），慢轨的影响 12 秒后自然消退；
- **非对称平滑**：盘读顺了立即给好消息，真变慢时数字缓慢爬，不会一跳一截；
- **样本不足说「正在估算…」**：开头 1.5 秒 / 32 扇区以内不给假数字，收尾显示「即将完成」；
- **显示按档位约整**（<1 分按 5 秒、<10 分按 15 秒、更久按 1 分），抖动被档位吃掉；
- **修了两个量纲 bug**：整盘流程原来拿「本轨已用时间」除以「全盘已完成扇区」，
  速度显示也用「本轨字节 ÷ 全盘时间」；现在 elapsed / bytes 都是整盘累计。
  另外「同名文件跳过」的轨现在也计入已完成，进度条不会停在 90% 不动。

## 0.33.0（查不到元数据：CDDB 镜像 + 代理 + 说清原因）

这张盘「抓不出元数据」不是解析 bug，实测结论：

- MusicBrainz 有响应，但这张盘（discid `jCz7JPOv0e14IuzcyS.StppLPio-`）**在库里没有记录**（404）。
  用 libdiscid 规则独立重算过同一个 id，说明不是 id 算错。
- gnudb（CDDB）**网络层不通**：`gnudb.gnudb.org` TCP 80/443 在本机都是 connect timeout
  （`Test-NetConnection` 23 秒仍失败），插件以前会重试 4 次，等于白等约 48 秒。
- `freedb.freedb.org` / `cddb.musicbrainz.org` 已 NXDOMAIN；`freedb.dbpoweramp.com` 能连，
  但对本盘返回 `401 No such CD entry`。

因此这一版做三件事：

- **CDDB 镜像轮换**：`GnudbClient` 依次试 `gnudb` HTTP → `gnudb` HTTPS → `freedb.dbpoweramp.com`，
  连不上的镜像记进 `deadMirrors`，本次运行不再等它；日志里能看出是哪个镜像失败。
- **连接超时压到 4 秒、连不上不再重试**：`Http.configure()` 统一设置，
  `UnknownHostException` / connect timeout 直接短路，避免面板看起来卡死。
- **新增设置「HTTP 代理（可选）」（5 · 元数据）**：写 `127.0.0.1:7890` 之类即可走代理，
  空 = 直连。改完不用重启宿主，每次查询前会重新读设置。
  面板空态也会区分「这张盘没记录」和「网络不通，可以填代理」，并仍可改用手动填写。

## 0.29.3（页内区块 + 兜底坞双挂，杜绝「整块消失」）

- 0.29.2 之后出现过「面板直接不见了」：页内 hook **挂成功了，但那个子组件在当前状态下不会被组合**，
  于是既不显示页内区块，也不再走原来的整页 fallback。挂载成功 ≠ 会渲染。
- 现在两套 hook 同时挂：页内区块每次组合都打一次心跳（`PanelState.inlineBeatAt`），
  兜底坞读心跳——**1.5 秒内没有心跳才显示自己**。页内能渲染就只有页内；不能就自动由坞接管，
  不会出现空白。
- 「检查面板挂载」会告诉你：页内 / 坞、以及页内**已渲染次数**（0 次即「挂上了但从不组合」）。

## 0.19.0 重读位置记录（哪一段扇区读不稳）

之前只知道「这一轨重试了 17 次」，不知道重试在哪里。日志和错误报告现在会列出具体扇区区间：

```
重试位置      : LBA 1200-1215(16), LBA 3000-3015(16)
```

- 只在「校验不一致触发重读」时记录（不是每次 IO 重试），所以它指向的是**数据真的读不稳**的位置。

## 0.18.0 静音法间隙探测（Test Gaps On Silence）

设置里新增 **「间隙探测方法」**：

- **子通道 Q（默认）**：读 Q 子通道，看盘上写的 `INDEX 00`。作者怎么标就怎么认。
- **波形静音**：不看索引，直接看波形——从音轨起点往前逐扇区算峰值，连续 ≤ -60 dBFS 就算间隙。

为什么两个都要：Q 法依赖盘上真的有 `INDEX 00`。自刻盘、部分老盘、以及某些把 `INDEX 00`
报成 `INDEX 01` 的驱动器会让 Q 法得到 0，而波形上明明有几秒静音。反过来，现场盘可能
在非静音处也标了间隙——那时只有 Q 法是对的。EAC 同时提供这两种，是有原因的。

实现要点：

- 峰值按小端 16 位取绝对值最大者，`20*log10(peak/32768)`；全零扇区返回 `-inf`。
- 阈值、扫描上限（默认 75 扇区 = 1 秒）、下界都可配；读失败立即停，不猜。
- 与间隙处理三档（附加/归入下一轨/丢弃）正交：先定「间隙有几个扇区」，再定「归谁」。

## 0.15.0 缓存击破 + 通用外部编码器

### 击破驱动器缓存（secure mode 的正确性补丁）

双读校验有个隐藏前提：**两次读真的都到了盘上**。不少驱动器会把刚读过的扇区缓存起来，
于是第二次读命中缓存、和第一次「一致」→ 校验通过，但盘上数据可能是错的。

新设置「击破驱动器缓存」打开后，每次重读同一块之前先读一个**远端扇区**（离当前块约 4000 扇区），
把刚读的扇区挤出缓存。代价是每块多一次单扇区读（约 +6% 时间），换来校验真的在验盘。
EAC 靠内置驱动器特性库判断「这台会不会缓存」，我们没有那个库，所以做成开关 + 文档说明。

### 通用外部编码器（EAC 的 External compressor）

「输出格式」新增 **外部编码器（自定义命令行）**，三个新设置：

| 键 | 说明 | 默认 |
| --- | --- | --- |
| `encoderExe` | 可执行文件；可只写名字走 PATH | `flac` |
| `encoderArgs` | 参数模板，`%in%` `%out%` `%tracknr2%` `%title%` 等 | `-f -s -5 -o "%out%" "%in%"` |
| `encoderExt` | 产物扩展名（不含点） | `flac` |

- 先展开占位符**再**切分参数，所以含空格的路径只要在模板里加引号就不会被拆坏；
  `""` 表示字面引号，长的占位符优先（`%tracknr2%` 不会被 `%tracknr%` 咬掉）。
- 编码器退出码非 0、超时（默认 1800s）或没产出文件都会**删除半成品并保留 WAV**，日志写明原因。
- 这样 `flac` / `opusenc` / `ffmpeg` / `qaac` 都能接；只是 FLAC 专用的标签与内嵌封面
  仍然只在内置 FLAC 路径里做（外部编码器不猜格式）。

## 0.14.0 读命令可切换 + 自动退让（EAC 的 Extraction command set）

有些驱动器不认 MMC 标准的 READ CD（0xBE），只认厂家命令或老式 READ(10)。
现在设置页「抓轨」组有 **音频读命令**：`自动 / 标准 MMC / MMC + C2 / READ(10) / 厂家 0xD8（实验性）`。

- **自动退让**：`auto` 起手用标准 MMC，若驱动回 *ILLEGAL REQUEST*（或 ASC 0x20–0x26，即「不认识这条 CDB」），
  自动换 READ(10)、再不行换 0xD8，并在日志里写清换了哪条、为什么换。
- **只对命令级错误退让**：L-EC / CIRC / 超时这类**真读错误不会换命令**——命令是通的，换命令只会掩盖问题。
  介质不兼容（ASC 0x30）也不换，那是盘的问题。
- **「①.3 探测可用读命令（只读）」**：逐条读 1 个扇区，直接告诉你这台驱动器认哪几种读法；
  探测完把偏好复位成 `auto`，不会把探针结果带进正式抓轨。
- 日志的「设置摘要」里会记录 `readCommand`，事后能对上是哪条命令抓的。

CDB 布局（12 字节，大端）：

| 命令 | CDB[0] | 关键字段 |
| --- | --- | --- |
| `mmc` | `0xBE` | `[1]=0x04`（CD-DA）、`[2..5]`=LBA、`[8]`=扇区数、`[9]=0xF8` |
| `mmc-c2` | `0xBE` | 同上，`[9]=0xFA`（要 C2 指针） |
| `read10` | `0x28` | `[2..5]`=LBA、`[7..8]`=扇区数（16 位） |
| `d8` | `0xD8` | `[2..4]`=LBA（24 位）、`[6..8]`=扇区数 |

## 0.13.0 同一张盘再抓不再联网

`album.json` 现在有两个消费方向，形成闭环：

- **写出**：设置里开「在专辑目录写入 album.json」后，抓完会在专辑目录写一份，**同时**在
  `<输出根>/.saltrip/album-<DiscID>.json` 存一份每盘缓存。
- **读回**：开「抓过的盘优先用上次的元数据」（默认开）后，同一张盘再抓会先看这份缓存，
  命中就**跳过全部联网查询**，直接按缓存里的名字建目录/命名文件。

实际用法：

1. 第一次抓某张盘，元数据抓错了（比如 MB 选错版本）→ 直接编辑专辑目录里的 `album.json`。
2. 把改好的文件复制到 `<输出根>/.saltrip/album-<DiscID>.json`（或直接在首次抓轨时开启写缓存）。
3. 再次抓同一张盘 → 名字、音轨标题、年份全部按你改的来，不联网、不重复踩坑。

缓存键是 DiscID（不是目录名），所以改名字、换目录模板都不会让缓存失效；换盘则必然不命中。
关掉「优先用上次的元数据」即回到每次联网查询的行为。

## 0.12.0 日志更像 EAC + album.json 可复现

日志（`.log`）每轨那行补了三样 EAC 有、之前没有的信息，并加了全盘汇总：

```
轨道
------------------------------------------------------------
轨 起始LBA   扇区数   时长      峰值dBFS  质量    CRC32     重试  用时  测试CRC
01         0    20114  0:04:28        0.0  100.0%  F3B439F2     0   26.6s   F3B439F2
02     20114    18000  0:04:00       -0.3   99.9%  1A2B3C4D     2   24.1s   1A2B3C4D（不一致）

合计重试      : 2
整体质量      : 99.95%
最高峰值      : 0.00 dBFS
```

- **峰值 dBFS**：抓轨时顺带算每轨 16-bit 峰值（`SecureRip.peakLevel`），静音写 `-inf`。
  不用再拿别的工具测「有没有削波」。
- **质量 %**：`100 × (1 − 重试扇区数 / 扇区数)`，比 EAC 更悲观——EAC 只统计「重读后仍不一致」的扇区，
  这里把所有重试都算进去，宁可低估。
- **测试CRC**：开了 Test & Copy 时并排显示测试通道的 CRC，不一致会标「（不一致）」，
  一眼能看出哪轨两次读结果不同（EAC 是把两行分开写）。
- **开关**：设置页「输出与命名」组新增 **在专辑目录写入 album.json**（默认关）。
  打开后抓完会把解析到的元数据写一份 `album.json` 到专辑目录，字段与外部覆盖文件同构，
  可以直接手改再用它重抓；下次同盘也能离线复用，不必再联网。
  抓不到元数据时会写占位名（未知艺术家/未知专辑），不会写出空标题把目录名带偏。

## 0.11.0 间隙三档处理（EAC 的 gap handling 全对齐）

原先只有一个「把间隙计入音轨」的开关，语义含糊；现在改成与 EAC 一致的三档
**间隙处理方式**（设置页「校验与元数据」组）：

| 模式 | 音轨文件范围 | CUE | 说明 |
| --- | --- | --- | --- |
| `append` 附加到上一轨（默认） | `[INDEX 01, 下一轨 INDEX 01)` | 只有 `INDEX 01 00:00:00` | EAC 默认；尾部间隙在上一轨文件里 |
| `prepend` 归入下一轨（非标准） | `[INDEX 00, 下一轨 INDEX 01)` | `INDEX 00 00:00:00` + `INDEX 01 <gap>` | EAC 的「Multiple WAV Files With Gaps (Noncompliant)」 |
| `leaveout` 丢弃间隙 | `[INDEX 01, 下一轨 INDEX 00)` | 只有 `INDEX 01 00:00:00` | 间隙不落盘 |

- 选 `prepend` / `leaveout` 时会**自动做整盘间隙预扫**（否则算不出边界），日志会写每轨的 INDEX 00 位置。
- `leaveout` 用「下一轨 INDEX 00」当截止点；如果子通道读不到间隙，会退回 `append` 并在日志说明。
- **整盘镜像与 `prepend`/`leaveout` 互斥**：这两种模式下音轨边界不连续，拼接出来的镜像会缺/重采样，
  所以会自动跳过镜像并在 `.log` 里写明原因（逐轨文件照常输出）。
- 旧配置里的 `includeGaps = true` 会自动迁移成 `prepend`；`RipResult.gapSectors` 的语义也统一成
  「真的写进本文件的间隙扇区数」（`append`/`leaveout` 恒为 0）。
- 新增测试：`leaveoutTrimsTrailingGap`、`prependModeMovesGapIntoFollowingTrack`（校验文件大小与 CUE
  的 `INDEX 00/01`）、`leaveoutModeTrimsGapBeforeNextTrack`、`imageModeIsSkippedWhenGapModeIsNotAppend`。

## 0.10.0 FLAC 标签与内嵌封面（不用 metaflac）

抓轨输出 FLAC 时，标签与封面由插件自己写进 FLAC 元数据块，**不调用 `metaflac`**：

- 实测 `metaflac --set-tag` 在 Windows 上按 ANSI 代码页写字符串：`TITLE=道` 落盘成
  `93 B9`（Shift-JIS），`Fantôme` 的 `ô` 直接丢失。`--import-tags-from` 也不可靠。
  这是 metaflac 的老问题，不是参数用法问题。
- 所以 `encode/FlacMeta.kt` 直接按 FLAC 规范改元数据块：`fLaC` + `[lastFlag|type][24bit len][payload]` +
  音频帧流。只重写 VORBIS_COMMENT（type 4）与 PICTURE（type 6），音频帧逐字节搬运，
  写完用 `Files.move(REPLACE_EXISTING)` 原子替换。
- 标签一律 UTF-8（`TITLE / ARTIST / ALBUM / ALBUMARTIST / DATE / GENRE / TRACKNUMBER /
  TRACKTOTAL / DISCNUMBER / TOTALDISCS / ISRC / COMMENT`），`ARTIST` 缺省时回退专辑艺术家。
- 封面走 PICTURE 块（type 3 = front cover，自动从 PNG IHDR / JPEG SOF 读尺寸），
  与磁盘上的 `cover.jpg` 同时保留（播放器认哪个都能用）。
- 设置页新增 **写入 FLAC 标签**、**把封面内嵌进 FLAC** 两个 switch（默认都开）。
- 验证方式：`FlacMetaTest` 8 例（UTF-8 字节、块字段、音频帧不变），
  `FlacMetaLiveTest` 用真 `flac.exe` 编码后改写，再跑 **`flac -t`** —— 解码自检通过说明音频流没被改坏。

## 0.9.0 整盘间隙预扫 + 一个真实的间隙探测 bug

设置页新增 **抓轨前预扫间隙**（默认关）与按钮 **①.5 间隙预扫（只读）**：

- `DiscAnalysis` 一次算出每轨 INDEX 00 位置、轨长、间隙毫秒，面板里显示成表格
  （`轨 / INDEX 01 / 时长 / 间隙`），日志里落一行，可在开抓前判断这张盘有没有预间隙。
- 打开「抓轨前预扫间隙」后，抓轨阶段直接复用预扫结果（`RipEngine.ripTrack(knownGapSectors=…)`），
  不再逐轨重复读 Q 子通道，整盘少一半 Q 读。
- **顺带修掉一个一直存在的 bug**：逐轨间隙探测的下界原本传的是「上一轨结束位置」，
  而 TOC 的上一轨结束恰好等于本轨 INDEX 01，导致扫描区间为空、**永远探测不到间隙**。
  现在下界改为「上一轨 INDEX 01」，与预扫口径一致。

## 实现要点

- **传输**：`java.lang.foreign` 直接调 `DeviceIoControl` + `SCSI_PASS_THROUGH_DIRECT`（宿主已开 `--enable-native-access`）。
  句柄需 `GENERIC_READ|GENERIC_WRITE`；每次传输最多 **16 扇区**（17 扇区起 `err=87`）。
- **读命令**：`READ CD (0xBE)`，CDB `BE 04 [LBA BE24] 00 00 [n] F8 00`；`F8` 含 user data + C2 + 子通道（本机验证可用）。
- **校验**：`secureMode` 时同块读两遍逐字节比对，不一致重读，最多 `maxRetries` 次，保留最后一次结果并计数。
- **元数据**：`discid` 走 MusicBrainz（1 req/s），封面走 Cover Art Archive `front-<size>`；
  gnudb（CDDB 协议）作为回退，`hello` 需「已注册客户端名 版本 邮箱」。
- **CRC32**：对每轨 PCM 数据（不含 44 字节 WAV 头）计算，日志给出单轨与合并指纹，用于与 EAC 对账。

### 0.21.0 日志补 TOC 表与 CD-TEXT 状态

日志开头现在有两块新信息：

- **`TOC` 段**：每轨的起始 LBA 与时长（`mm:ss:ff`，帧为 75 分之一秒）。抓轨出错时，
  看这一段就能判断「文件长度不对」是 TOC 读错还是读取越界，不必再回插盘复现。
- **`CD-TEXT : 有/无/未检测`**：明确写出这张盘有没有 CD-TEXT。以前只能从「曲名像不像
  CD-TEXT 来的」猜；现在日志自身就给出答案，也方便判断「驱动不导出」还是「盘上没有」。


### 0.22.0 只测不写（Test only）+ 真机验证修掉一个静默错误

新增按钮「只测不写（Test only）」：按正式抓轨的参数把整盘读一遍，只报告每轨 CRC 与错误，
**不写任何文件**。用途是先确认这张盘能不能顺利读出来、坏轨在哪，再决定是否真正抓取。
面板与日志会给出每轨扇区数、CRC32、重试次数、用时，末尾一行汇总「全部读通 / N 轨有错误」。

同时，真机联调抓到并修掉一个**静默数据错误**：

- READ CD(0xBE) 的 LBA 字段是 `CDB[2..5]` 四字节大端。自 0.14.0 引入「读命令可切换」起，
  代码把它写成了三字节（`CDB[2..4]`），于是 `lba=16` 实际请求的是 `0x1000=4096`。
  在 lead-out 之前驱动不报错、只是**读回错误的扇区**，越过 lead-out 后报 `ASC=0x21`
  （LBA out of range），再触发读命令回退链，最终以「0xD8 不被支持」这种误导性错误失败。
- 影响面：0.14.0–0.21.0 的所有真机抓轨。单轨第 1 轨（lba 0）恰好正确，跨轨/整盘必错。
- 修法与守护：`ReadCommands.kt` 改用 `be32(cdb, 2, lba)`；新增回归用例
  `nonZeroLbaKeepsItsLowByteInCdb5`（lba=16 必须落在 `CDB[5]`），并把原有 CDB 布局用例
  的期望值一并改成四字节——它此前**把错误固化成了断言**，所以离线测试一直是绿的。

## 0.2.1 新增：EAC 式读取策略、间隙写盘、峰值电平

- **出错恢复质量**（设置页 list errorRecovery）：low 只读一次；medium 要求连续 3 次一致；high 要求连续 5 次一致，单块最坏读 82 次（EAC 同口径）。实现见

- **峰值电平**：每轨抓完算 16-bit 峰值，日志记 peak=-0.12dBFS。

## 0.2.2 新增：断点续抓、错误报告、驱动器健康检查

- **断点续抓**（设置页 switch `resume`，默认开）：目标 WAV 已存在且是合法 RIFF/WAVE 时，
  从已有数据长度推算已完成扇区数，截掉半截扇区后接着写；已写部分的 CRC 会用 `crcFile` 重算，
  所以续抓后的单轨 CRC 与一次抓完完全一致。用 `WavWriter(path, append = true)` 实现，
  对「不是 WAV / 太短」的文件自动重建，不会污染损坏文件。
- **错误报告**（`<专辑>.errors.txt`）：只要出现 `errors > 0` 的音轨或流程备注（封面/CUE/offset 失败等）就生成，
  纯文本、一行一条，方便直接贴到 issue。正常抓轨不产生该文件。
- **驱动器健康检查**（诊断组按钮 `healthCheck`）：INQUIRY + TEST UNIT READY + READ TOC，
  全部只读、不发任何实验性 CDB；**12 秒看门狗**——设备在驱动层挂起时直接 toast
  「驱动器 12 秒无响应…禁用/启用设备或重启」，避免用户再遇到「点一下界面卡住」时无从判断。
- 注意：健康检查与扫描都跑在独立 daemon 线程，不会占用抓轨用的单线程执行器，也不会阻塞宿主 UI 线程。

## 0.2.3 新增：FLAC 输出（外部编码器，与 EAC 同策略）

- 设置页新增：`format`（WAV / FLAC）、`flacExe`（默认按 PATH 找 `flac`）、`flacLevel`（0/3/5/8）、`keepWav`。
- 编码调用：`flac -f -s -<level> -o <out.flac> <in.wav>`，用 `ProcessBuilder` 传参数数组**不经 shell**，
  所以 `宇多田ヒカル/Fantôme` 这类路径不会被代码页破坏；失败/超时会删掉半成品 `.flac` 并在日志与
  `.errors.txt` 里留一条「已保留 WAV」的备注，抓轨本身不因此失败。
- CUE 会自动写 `FILE "…flac" WAVE`（fb2k / foobar2000 / EAC 均按此识别）。
- CRC32 仍是**对解码后的 PCM** 计算，与输出格式无关，所以 FLAC 与 WAV 的日志 CRC 可直接对比。
- 自测：`FlacEncoderTest` 覆盖参数顺序/等级钳制/PATH 查找/编码器缺失时的清理；
  本机若有 `flac.exe`（例如 EAC 目录自带的那个）会额外跑一次真实编码并校验 `fLaC` 魔数。

### 挂载规则（反编译宿主实现得到，升级后若失效会安静降级）

`HookRegistrar.afterComposable(className, methodName, inClass, parameterTypes, priority, hook)` 的匹配条件是：

1. `className.methodName` 必须是「返回 void、且恰好有一个 `androidx.compose.runtime.Composer` 参数」的 composable；
2. `parameterTypes` 与「Composer 之前的参数类型名列表」**全等**（传 `null` 表示不限）；
3. `inClass` 的字节码里对该方法的调用必须**恰好一处**，否则报 `UI call missing or ambiguous`。

当前目标（Salt Player 1.19.0）：

| 项 | 值 |
| --- | --- |
| className | `androidx.compose.ui.ݩ` |
| methodName | `Ϳ` |
| 描述符 | `(Landroidx/compose/ui/ঘ;Landroidx/compose/runtime/Composer;II)V` |
| inClass | `com.xuncorp.voxzen.ui.navigation.ComposableSingletons$AppNavigation_desktopKt` |

`PanelMount` 先按 `parameterTypes = ["androidx.compose.ui.ঘ"]` 注册，失败再用空列表重试；
两次都失败只写日志（`panel mount gave up`），**不会**让插件加载失败，用户仍可从设置页操作。
注册失败的原因通常是宿主升级导致混淆名变化——此时更新 `PanelMount` 里的三个常量即可。

### 为什么不用 Material3 / 宿主 ui 组件

宿主自带 `androidx.compose.material3`（1264 个类），但 `com.moriafly.salt.ui.**` 是混淆的。
面板只用 `foundation` + `ui` 的基础组件（`Column/Row/BasicText/background/border/clickable`），
颜色写死为深浅主题都可读的中性色板，这样既不会因宿主换主题而低对比度，也不会因组件库
版本/混淆变化而在组合期崩溃。

### 自测

- `verify_hook_target.py`（仓库根）：直接解析宿主 `ffmpeg-x64.dll` 里的 class 字节码，
  校验目标类存在该方法、描述符匹配、调用者对该方法的 `Methodref` 恰好一处——**不启动宿主**即可验证上面四个常量。

## 0.3.1 新增：元数据选择与手工覆盖

日版/老盘最常见的失败不是「查不到」，而是「查到了错的版本」——同一 DiscID 常对应日版、港版、

## 0.3.2 新增：CD-TEXT 与多碟

**CD-TEXT**（`scsi/CdText.kt`）＝ EAC 的「CD-Text」功能，从 `READ TOC format 5` 解析曲名/艺术家/流派。
优先级排在网络之前（盘片自带的信息最不容易错），但绝大多数压制 CD 没有 CD-TEXT，
读不到会静默跳过——两版测试盘（1987 松田聖子、2016 宇多田ヒカル「Fantôme」）实测都是空的。

- 编码：`0x8F` size info 的字符集字段 → Shift-JIS / ISO-8859-1；没有该 pack 时按字节特征猜。
- 诊断组新增「检测 CD-TEXT（只读）」：结果写日志与面板，用来判断是「盘没有」还是「读法不对」。
- 设置项「读取 CD-TEXT」（默认开）。

**多碟**：`碟号（0=自动）` / `总碟数（0=自动）`。总碟数 > 1 且文件夹模板没写 `%discnumber%` 时自动加 `CD1/CD2`。

自测：`CdTextTest`（空报文判 null、多 pack 长标题、SJIS 经 0x8F 声明、无 0x8F 时自动识别、Latin-1、
占位名、CD-TEXT 与 MB 合并时谁覆盖谁）——全部不需要光驱。

## 0.8.0 整盘镜像（Copy Image）

设置页「输出与命名」新增 **整盘镜像（单文件 + CUE）**：

- 流程仍是**逐轨安全抓取**（双读比对 / C2 / gap / 断点续抓全部保留），抓完后按顺序把各轨的数据段拼成一个
  `<艺术家 - 专辑>.wav`，删除逐轨文件，并生成只含一个 `FILE` 的 CUE。
- CUE 里的 `INDEX 01` 是**相对镜像起点的绝对时间**（不是 00:00:00），否则播放器会把每轨都当成从 0 开始；
  有 INDEX 00 间隙时同样按绝对位置写。
- 与 FLAC 组合时会先把镜像 WAV 编成 `flac`，CUE 自动改成 `FILE "….flac" WAVE`；`保留 WAV` 关闭时删除中间 WAV。
- 代价：拼接期间临时占用约两倍空间（余量预检已按两倍计算），失败时保留逐轨文件并在日志/`.errors.txt` 里说明。

## 0.7.0：让抓轨流水线可以「没有光驱」也测

这一版没有加功能，只做一件事：**把不可测的部分变可测**。

### 为什么

之前 8 项功能只能靠你真机验证（面板、整盘、续抓、双读、C2、CD-TEXT、换碟、弹托盘），
而 0.5.0 那个「续抓与另存打架」的 bug 恰恰是推理看不出来的——两个功能各自正确、组合起来错。
这类 bug 只有端到端测试能挡住。

### 做了什么

- 新增 `rip/TrackSource.kt`：抓轨真正需要的 5 个方法（读扇区 / 读进缓冲 / 读 C2 / 读 Q / 单次上限）。
  生产实现 `CdTrackSource` 包一层 `CdDevice`，行为完全不变。
- `RipEngine.ripTrack(..., source: TrackSource? = null)`、`AlbumRipper.rip(..., source: TrackSource? = null)`。
  传 null 时走真实光驱（默认）；传假驱动器时自动跳过 CD-TEXT、换碟守卫、弹托盘这些真实 IOCTL。
- 测试侧 `FakeTrackSource`：按 LBA 生成确定性扇区，可注入「首读失败」「首读内容不对」「C2 报错」
  「驱动不支持 C2」「指定 Q 子通道」。
- 新增 `RipPipelineTest` 8 例（整轨 CRC、**续抓 CRC 一致**、verify 重试、C2 降级、C2 报错重读、
  取消、gap 探测、gap 计入）与 `AlbumPipelineTest` 5 例（整盘命名/CUE/日志、只抓选中轨、
  Test&Copy、二次运行另存、中途取消）。

### 顺带修掉一个真 bug

写测试时发现：`checkC2` 只捕获 `ScsiException`，如果驱动器对 C2 命令返回别的异常
（`IOException`、超长返回、固件怪响应），**整轨抓取会被中断**。
C2 只是加速/诊断手段，不该有一票否决权。现在改成任何异常都只降级关掉 C2 并记日志。

另外记一条测试教训：注入错误必须打在 chunk 起点（16 扇区的倍数），
否则假驱动器根本看不到那次错误——第一版测试就是这样写错的。

测试 151 用例 0 失败 11 跳过（新增 13 例，全部无需光驱）。


## 0.6.1：修一个自己引入的 bug + 输出目录自检

## 0.6.0 新增：多光驱与驱动器控制

- **指定光驱盘符**（`driveLetter`）：`F` / `F:` / `\\\\.\\F:` 都认。留空＝第一台。

## 0.5.0 新增：可控性与事故防护

抓轨是「跑几十分钟才出结果」的操作，这一版重点不是加功能，而是**让失败可控、让损失可避免**。

- **只抓部分音轨**：`trackSelection` 支持 `1-5,8,10-`（EAC/foobar 风格），空＝整盘。
  非法片段（`0`、`5-3`、`abc`、多余逗号）一律忽略而不是报错；日志回显压缩后的清单（`1-3,8,10`）。
- **同名文件策略**（`overwritePolicy`）：默认 `suffix` 加 ` (2)` 另存，**永不覆盖**；
  也可选 `overwrite` / `skip`（跳过该轨并记进备注）。整组命名（WAV/CUE/日志）一起顺延，
  避免 CUE 的 `FILE` 指向上一张盘的残留文件。
- **磁盘余量预检**：开抓之前按 `扇区×2352×1.15 + 8 MB` 估算（不保留 WAV 时再 ×1.5，
  因为编码期间两份同时在），不足直接报「磁盘空间不足：需要约 X，可用 Y」，
  不写到一半才炸出一只半截 WAV。
- **换碟守卫**（`guardDisc`）：每轨开始前重读 TOC，只要 lead-out 或任一轨起始 LBA 变了就中止，
  并说明「检测到光盘已变更（lead-out A → B），为避免把两张盘的音轨混在一起」。
  已抓取的音轨保留在输出目录。
- 测试 122 用例（新增 TrackSelectionTest 7、RipSafetyTest 12）。

「没有盘」不算故障：清掉面板上的旧盘信息、按钮随即变灰；只有真正的设备故障才指数退避到 30 秒
（驱动挂起时频繁重试只会继续挂）。抓轨进行中（`PanelState.busy`）完全不轮询。

**元数据候选自选**（`MetadataCandidates`，用户反馈 3）：以前只能靠 `releaseIndex` 盲选第 N 个发行版。
现在面板上直接铺最多 3 个候选（250px 缩略图 + 艺人 · 专辑（年份） · N 轨），点一下即换版本；
选中的版本会写进 `<输出根>/.saltaudiocopy/album-<DiscID>.json`，之后再抓同一张盘直接沿用。
「刷新元数据」会重新查询并重建候选。

**封面默认原图**（用户反馈 6）：`coverSize` 默认改为 `0`（= Cover Art Archive 的 `front` 原图），
候选列表里仍用 250px 缩略图，只有点选后才下载原图。设置页可选 原图 / 500 px / 1200 px。

**其他**：扫描到音频 CD 后自动查一次元数据（不必再点按钮）；面板按钮「查元数据」改名「刷新元数据」。

自测：274 用例 0 失败（新增 `CandidateAndWatchTest` 6 例：封面 URL 策略、候选标题、选择越界钳制、
「没盘」与「数据盘/真故障」的区分、异常包装下的 sense 判定、坏图解码不抛）。

## 0.29.4 — 改成整宽底部坞（回到可靠的挂载方式）

0.29.0–0.29.3 想把面板塞进宿主页面流（方案 D），两次都失败：
`afterComposable` 在页面 Column 的子组件上挂成功，但那个子组件要么当前状态不组合、
要么被放进零尺寸布局，结果既没有页内区块、也不再走兜底坞（表现为「面板消失」）。
宿主这个页面的内部结构不是给插件留的插槽，继续猜布局风险大于收益。

0.29.4 只保留**整页 hook**（0.27/0.28 已验证稳定），把面板做成设计稿的样子：

- 整宽横向坞，贴页面底部，上移 96dp 避开宿主播放条（不再压住任何东西）
- 玻璃面板：宿主 `surfaceContainerHigh` + 92% 不透明 + 1px `outlineVariant` + 20dp 圆角 + 阴影
- 单行：封面 / 专辑与盘摘要 / 输出路径预览 / 动作按钮；运行时同一行换成进度条 + 速度 + ETA
- 设置在原位向下展开（模板输入框 + 变量块 + 安全双读开关），不再另开窗口
- 所有颜色、字号取自 `MaterialTheme`，深浅主题跟随宿主；不再自己写死配色

`PanelMount` 里的 `inline` 字段保留但恒为 false（仅兼容诊断与旧测试）。

## 0.29.9 — 去掉 400ms 轮询

- 按用户要求改成「每次合成时读一次宿主外观」：打开 CD 工具箱、面板状态变化、重新进入该页面时都会重新读，
  不再有后台定时器。
- 日志从 `theme changed` 改成 `theme composed`，只在深浅真的变化时写一条，便于排查。

## 0.29.8 — 宿主切深浅后自动跟随

- 0.29.7 只在合成时读一次宿主外观，切深浅后不会重组（`AppConfig.lightDarkTheme` 的 delegate 不是
  Compose 快照状态，读它不会订阅），所以一直停在上次读到的值。
- 现在每 400ms 对一次表（`hostDark()`），值变了写进 `mutableStateOf` 触发重组；同时在插件启动时
  和每次切换时把 `hostDarkHint()`（原始枚举值）写进日志，便于确认读到的到底是什么。

## 0.29.7 — 去掉外观选项，直接跟随宿主

- 删除了 0.29.6 里那个「外观：跟随系统 / 浅色 / 深色」选项（面板和配置页都删了）——这是插件的职责，不该让用户选。
- 改成直接读宿主：`AppConfig.INSTANCE.getLightDarkTheme()` 返回枚举，字段名虽然被混淆，但枚举常量的
  `Enum.name` 仍是 `"Dark"` / `"Light"` / `"FollowSystem"`，据此判定；读不到（宿主没加载该 API）时退回操作系统深浅。
- **修掉 0.29.6 的实际 bug**：主题包在了 `RipPanel()` 上，而面板实际是由 `PanelMount.Content` 渲染的，
  那条路径根本没套主题 → 仍然落到 Material3 缺省配色（淡紫）。现在 `PanelMount.Content` 里直接
  `SaltRipTheme { DockPanelBody() }`，两条路径都过主题。

## 0.29.6 — 自带中性主题（彻底去紫）+ 设置界面减负

面板不再借用宿主的 `MaterialTheme`（宿主用的是自己的 SaltTheme，插件取不到，之前一直落到 Material3
缺省配色上，那就是那层淡紫的来源），改为自带一套中性明暗配色：

- 浅色：白底 `#FFFFFF`、次层 `#F4F4F5`、正文 `#16161A`、次要文字 `#6B6B6F`、描边 `#DCDCE0`；
- 深色：`#1B1B1E` / `#27272B` / `#F0F0F2` / `#A2A2A8` / `#3C3C42`；
- 主按钮「黑底白字 / 白底黑字」反转，进度条与选中态都用正文色；除错误色外**所有颜色通道差 ≤ 6**（无任何色相），
  由 `NeutralThemeTest` 守住。

设置区可切换「外观：跟随系统 / 浅色 / 深色」（配置页与面板内都有），立即生效、写入设置 `appearance`。

其他改动：
- 模板输入框不再显示「正在编辑这个模板」，改成聚焦/点击即选中、边框变深；
- 变量块删掉 `轨号 1`（`%tracknr%`），只留 `轨号 01`（`%tracknr2%`，EAC 的两位轨号是更常用的一种），避免两个看起来一样的块；
- 面板本体不透明（不再依赖宿主背景透过率），描边用主题描边色。

> 说明：宿主 1.19.0 的 salt-ui 类名在运行时被混淆，`SaltTheme` / `SaltColors` 只在构建期存在，
> 直接引用会 `NoClassDefFoundError`；因此「和宿主 SaltTheme 完全一致」无法做到，只能做到观感一致的中性方案。
